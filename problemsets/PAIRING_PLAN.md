# Teaching-order pairing plan

The end-of-chapter bank remains comprehensive. Weekly packets are curated pathways through it. Each packet selects a small hand-solvable seed and then expands one named feature with a reproducible Codex, Python, or Lean artifact. Stable textbook problem identifiers are retained so the packet, book, and private solutions can be cross-checked.

Appendix A supplies an optional Lean and proof-writing workshop. A.1 is the hand seed; A.2--A.4 scale from concrete finite relations to quotient orders, maximality, and order extensions. Formal coverage must be stated theorem by theorem: compilation of a nearby lemma does not certify the full textbook proposition.

## Pairing rule

For every planned packet, the scale-up must answer all four questions below before its tool instructions are written.

1. Which exact hand result is the regression test?
2. Which single axis is enlarged: goods, agents, observations, menus, states, or parameters?
3. Which identity or theorem supplies a deterministic check?
4. Which claim remains outside the artifact: model choice, empirical relevance, globality, identification, or welfare interpretation?

This rule prevents a simple example from becoming an unrelated coding exercise. It also permits different tools across topics: Lean is used where a precise general proposition is the object; Python is used where enumeration, calibration, or comparative statics is the object.
